# Firestore/Auth analysis

## Scope

- Web app: React 18 + TypeScript + Firebase modular SDK 12.
- Firebase project: `perfect-156b5`.
- Configured Firestore database: `(default)` in `nam5`.
- The Firebase CLI edition lookup timed out, so the implementation uses only
  standard modular Web SDK operations supported by the configured native
  Firestore database.

## Existing access patterns

- Application business data and legacy credentials are stored in Realtime
  Database.
- Firebase Authentication handles email/password sessions.
- Firestore was initialized but application account profiles were not written
  there.
- The only existing application Firestore query is an example read of
  `trainingProgress`; the current `firestore.rules` also defines unrelated
  `users`, `user_settings`, `links`, `events`, and `tickets` paths.

## New account data model

`accounts/{uid}` (private account profile):

- `uid`: string, required, immutable, same as document ID.
- `email`: string, required, must match the Firebase Auth token for self-create.
- `displayName`: string, required.
- `role`: `admin | student | jury | registration | jury-contest`, required,
  immutable for non-admins.
- `profileId`: string, required, immutable for non-admins.
- `status`: `active | disabled`, required.
- `username`: optional string.
- `contestId`: optional string.
- `migrationSource`: optional `legacy-rtdb`.
- `createdAt`: Firestore timestamp, required, immutable.
- `updatedAt`: Firestore timestamp, required.
- `migratedAt`: optional Firestore timestamp.

Reads are limited to the account owner or an admin because the document
contains PII. Self-registration can only create a `student` account. Other
roles require an existing admin.

## Operations

- Sign-in reads the authenticated user's own `accounts/{uid}` document.
- Legacy sign-in checks the existing RTDB model credentials, then offers an
  Auth + Firestore migration on the login page.
- Account creation writes Firebase Auth, Firestore `accounts/{uid}`, RTDB
  `users/{uid}`, and the business profile link.
- Admin provisioning uses an isolated secondary Firebase Auth instance so the
  administrator is not signed out.

## Devil's advocate review

- Public list/get of account PII: denied.
- Read/write another account: denied unless caller is admin.
- Self-assigned privileged role: denied; self-create is limited to `student`.
- Role/profile/UID/creation timestamp hijacking on update: denied.
- Invalid types, oversized strings, unknown fields, or missing required fields:
  denied by the validator on both create and update.
- Email spoofing on self-create: denied unless it matches the Auth token.
- Arbitrary timestamps: create/update timestamps must be recent.
- Schema pollution: denied by `hasOnly`.
- Unmatched Firestore collections: denied by default.

## Known boundary

Legacy passwords currently exist in RTDB model records. The migration removes a
model's plaintext password after success, but securing every remaining legacy
record requires a separate server-side credential migration and tighter RTDB
rules.
